# Decisions: redact

## Decisions
- Redact at `session.append`, the one event that sees every row before it is stored and sent (prompts, tool results, Claude's own blocks, attachments, notices). Rejected: rewriting results in `tool.call` after `next(e)`, because it misses prompts, attachments and plugin notes, and it leaves the transcript file raw.
- Also redact at `prompt.submit`. Rejected: relying on `session.append` alone, because the engine writes a `queue-operation` record and a command's `args` stamp from the typed text, and those are stored as made. `prompt.submit` cleans the text the screen echoes and the command args; the headless `-p` path still writes the queue record first (see Assumptions).
- Restore real values only inside `Edit`, `Write` and `NotebookEdit` arguments. Rejected: restoring in `Bash`, because the model could echo a placeholder into a network command and the real value would leave the machine.
- Restore a value only into a file that already holds it (as written, JSON-escaped, or with CRLF line ends), read with `$.fs.read` only when the arguments hold a placeholder; refuse the call otherwise. The invariant: a restore never puts a hidden value anywhere it was not already on disk, so a shell that can already read that file gains nothing. Rejected: restoring into any file (0.1.0), because Claude could `Write` a placeholder into `upload.ps1` and run it, write a temp file for `curl -d @file`, edit a notebook and run it with `nbconvert --execute`, or store the raw value in an auto-memory note. Rejected: a deny-list of script, notebook and memory file types, because any file can be uploaded or sourced by a later command (`curl -d @notes.txt`, `. .env`) and a list cannot name them all, while it would still block editing a script that already holds the key. Cost: a key typed in the prompt can no longer be written into a new file by Claude; the person pastes it in.
- Refuse an edit whose placeholder the vault does not know, unless the file already holds that placeholder as text. Rejected: passing it through (0.1.0), because the vault resets on `/clear`, `/resume` and restart while the transcript keeps the placeholders, so the edit wrote `[REDACTED:...]` into the file with no warning. The literal-text exception keeps edits to a doc that quotes a placeholder working.
- Refuse `Bash`, `PowerShell` and `Monitor` calls whose command contains anything shaped like a placeholder, known or not. Rejected: letting them run, because the brackets are a character class to `-replace`, `sed` and `grep`, so `(Get-Content .env) -replace '[REDACTED:...]','new' | Set-Content .env` rewrites the wrong characters across the whole file. The refusal tells Claude to use `Edit`.
- The restore hook and the shell refusal fail closed: a throw refuses the call. Rejected: the engine's default of skipping a failed hook, because then the edit runs with placeholders (or, before the check, a restored value) unchecked.
- Scan the first message's context blocks at `prompt.context` and the system prompt's `memory` section. Rejected: relying on `session.append`, because CLAUDE.md, its `@` imports and auto-memory are a context block, not a stored row. The hook rewrites the block text after `next`, so blocks other plugins add beneath are scanned too. Rejected: rewriting the `instructionFiles` list instead and letting the engine render the text from it, because the text the model gets would then be produced out of this hook's sight; the cost of rewriting the text is that the engine drops the file list for hooks above (measured in the 2.1.296 test kit). A scan that throws withholds every block's text.
- Rules added for formats common on a Windows lab machine: JSON-escaped pairs (`\"password\": \"...\"` in notebook source and MCP results), .NET `<add key="...Password" value="..."/>`, XML elements named for a secret, ODBC `PWD={...}`, `--password value` and PowerShell `-Password "value"`, and `sqlcmd`/`bcp`/`osql -P`. Each slot that can also hold a name (a config key, braces, a flag) rejects code names, environment variable names and template slots (`{Name}`, `#{Name}#`). Rejected: a bare `-P` rule, because `-P` is a port to mysql and a regex flag to grep.
- The generic rules no longer hide an all-caps environment variable name (`token: "GITHUB_TOKEN"`), a backticked code name in prose (`` auth: `useOAuthFlow` ``) or a value under 24 characters that opens with a vendor token prefix (`` token: `pypi-AgE...` `` in docs): a whole vendor token is caught by its own rule, which knows its length, and a cut-off one is no secret.
- Placeholders are `[REDACTED:LABEL#hash]` with an FNV-1a hash of a per-session salt plus the value. Rejected: HMAC with `node:crypto`, because the validator admits no bare import other than `claude-code`. Rejected: a counter, because the same value must map to the same placeholder across rows so edits and compaction summaries line up.
- Fail closed. A row the scanner throws on is stored as `[redact withheld this content ...]` with its `tool_use_id` kept. Rejected: fail open, because a redactor that stores raw on error is a redactor that stops working silently.
- PII rules are opt-in (`pii: true`). Rejected: on by default, because email addresses and phone numbers in code and docs are common and mostly harmless, and a redactor that hides a package author's email on every read gets switched off.
- One standing note in the `env_info_simple` section tells Claude the placeholders are opaque. Rejected: no note, because Claude otherwise asks the person for the hidden value or tries to "fix" the placeholder. Rejected: `prompt.compose`, because adding a section is more surface than appending to one that is always rendered.
- The vault lives in `$.state`, not `$.store`. Rejected: `$.store`, because real values would persist across sessions on disk.
- No `turn.complete` line and no `$.ui.notice`. Rejected: a per-turn summary, because the per-row `$.ui.log` line already says what was hidden and where; `$.ui.notice` is removed when the tool call resolves, which is before the result row is appended.
- The scrub logic is a pure module (`hooks/scrub.ts`) tested directly. Rejected: testing it through `session.append` in the kit, because on Claude Code 2.1.288 a test stub for `session.append` cannot answer (every answer must follow a `next`, and nothing is beneath the stub).

## Verified since
- The `$.ui.log` line draws in the terminal transcript as `redact: hid 1 AWS_KEY in your prompt`; the engine prefixes the plugin name, so the mod's own text carries none.
- Live interactive session on 2.1.288 (0.1.0, before the already-holds rule, which now refuses that `Write` into a new file): the prompt echo showed the placeholder, Claude's `Write` call carried it, the file on disk holds the real value, `/redact` reported one restoration. The session file held the placeholder in every conversation row; the only raw copy was the `toolUseResult` record of the `Write` (the file content as written), which the engine stores as made.
- An interactive session writes no `queue-operation` record at all; only the headless `-p` path does, and there it is written before `prompt.submit` runs.

## Assumptions not verified
- Subagent rows and subagent `Edit` calls pass through the same hooks with `agentId` set, as the types say. If wrong: a subagent could read a raw secret. How to check: run a subagent that reads a file with a fake key and grep its rows in the session file.
- Auto-memory (`MEMORY.md`) arrives inside the `claudeMd` context block, as `InstructionFile` kind `memory`, and the `memory` system prompt section holds at most the memory instructions. If wrong: memory text reaches the model through a route neither hook sees. How to check: put a fake key in `MEMORY.md`, start a session, and look for the `redact: hid ... in CLAUDE.md and memory` line.
- Nothing the model reads depends on the `instructionFiles` list the engine drops when the `claudeMd` text is rewritten. If wrong: a feature that lists loaded instruction files (`/memory`, `/context`) shows none while a key is hidden in one. How to check: hide a fake key in CLAUDE.md and open `/memory` and `/context`.
- `$.state` survives `/reload-plugins`, so placeholders made before a reload still restore. If wrong: an edit using an older placeholder fails and Claude re-reads the file. How to check: hide a value, run `/reload-plugins`, ask for an edit of that line.
